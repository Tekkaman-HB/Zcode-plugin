# 架构概览

## 系统边界

本插件是 ZCode CLI `app-server` 协议的**宿主客户端**：管理进程生命周期、复用桌面端凭据、把协议事件渲染成 VSCode webview UI。智能语义决策全部发生在 CLI 服务端，本仓库是确定性管道。

## 当前设计

分层（依赖严格单向向下）：

```text
extension.ts（激活中枢：装配/命令/工作区监听）
  ├─ environment.ts   环境探测（CLI 路径/node 回退/revision 指纹）
  ├─ account.ts       桌面端文件 → provider 快照（登录态监听）
  │   └─ credentials.ts  enc:v1 AES-256-GCM 解密
  ├─ serverManager.ts spawn app-server + 反向请求路由 + 重启退避
  │   └─ protocol/rpc.ts   NDJSON JSON-RPC 双向客户端（失败单路径：exitPromise）
  │   └─ protocol/types.ts 全部协议类型 + 通知守卫
  ├─ sessionController.ts 会话 CRUD/订阅/排队/看门狗/反向请求应答扇出
  └─ ui/chatProvider.ts   WebviewViewProvider（CSP/桥接分发）
      └─ ui/bridge.ts     两端消息契约（纯类型）
          └─ ui/webview/* 前端：chat.ts 应用壳（状态持有者）
              ├─ events.ts   协议事件适配（EventHost）
              ├─ queue.ts    交互焦点队列（QueueHost）
              ├─ menus.ts    弹层菜单控制器（MenuHost）
              ├─ render.ts / interaction.ts / permPreview.ts 渲染与交互卡
              └─ icons.ts / format.ts / markdown.ts / i18n.ts
```

- **Host 接口模式**：webview 子模块经窄接口（EventHost/QueueHost/MenuHost）回访 chat.ts 持有的共享状态，子模块互相零依赖。
- **数据流**：CLI stdout → rpc 解析 → sessionController 转发 → bridge 契约 → chat.ts onMessage → events 适配状态机 → 渲染层；反向：webview postMessage → chatProvider 分发 → sessionController → RPC。
- **协议层零 vscode 依赖**（smoke 直接复用）；webview 零 vscode import（可在浏览器预览验收）。
- 文件级地图（GEB L2/L3）见各目录 CLAUDE.md 与文件头，不在本文重复。

## 约束与取舍

- 排队/看门狗/重发扇出都是对协议行为（-32010 拒发、reannounce 重发、事件丢失）的宿主侧补偿，不可当冗余删除。
- 上下文用量取四路冗余源（session.updated/turn.completed/step-finish/messages 校准），以最早到达者渲染——协议如此，收敛为单源会丢实时性。
