# 50-planning — 目标说明

## 目标

记录现在进行到哪、接下来做什么、每个阶段改了什么。

## 放什么

路线图/阶段、实施计划、变更记录（changelog）。

## 不放什么

- 产品验收标准 → 10-product/验收标准.md
- 架构决策 → 20-architecture/decisions/
- 编码过程中的临时问题分析 → 80-dev/

## 命名格式

`路线图.md`、`变更记录.md` 使用固定名；其他临时计划使用 `YYYY-MM-DD-中文主题.md`，不得含空格。

## 内容格式

默认包含「目标与范围 / 里程碑与依赖 / 状态与验收」。frontmatter 至少包含 `status / owner / last-reviewed`。

## 编写要求

- `路线图.md` 与 `变更记录.md` 维护当前事实；临时实施计划按 `YYYY-MM-DD-中文主题.md` 命名。
- 计划写清目标、范围、负责人、里程碑、依赖、状态和验收条件，不按天堆叠进度流水。
- 方案或阶段实施完成时主动判断是否可收敛；先展示完成证据、已验证事实、10/20/30/40 目标、冲突和拟移动源文件，用户确认后才按目标目录 README 更新事实并移动清单中的源文件。日期前缀文件本地最后修改时间超过 7 天时轻量提醒。
