# Codex 插件界面复刻

## 目标与范围

用户要求 ZCode 插件的整体样式、交互逻辑与图标对齐其 VSCode 中的 Codex 插件，并已明确参照是 VSCode 插件。

唯一参照：本机 `openai.chatgpt`，显示名 `Codex – OpenAI’s coding agent`，版本 `26.1021.22027`。后续若参照自动更新，仍按本版本验收，避免目标漂移。

拟覆盖以下界面与状态：

| 区域 | 复刻内容 | ZCode 实现落点 |
| --- | --- | --- |
| 聊天导航 | 返回、标题、操作菜单、最近聊天、设置、新建；历史列表搜索与恢复 | chat.ts、menus.ts |
| 空态与消息流 | 欢迎页、用户气泡、助手正文、处理状态、消息操作、滚动行为 | chat.ts、render.ts、markdown.ts |
| 输入区 | 统一圆角容器、附件、文本输入、底部控制栏、发送/停止、排队 | chat.ts、icons.ts |
| 模型与权限 | 模型/推理强度选择、权限菜单、当前状态与键盘操作 | menus.ts、interaction.ts |
| 工具与代码 | 工具调用摘要、展开收起、代码块、文件差异、任务进度 | render.ts、permPreview.ts、todoPanel.ts |
| 浮层与反馈 | 菜单定位、搜索、选中、悬停、焦点、禁用、加载、错误 | menus.ts、styles.css |
| 主题与宽度 | 跟随 VSCode 明暗/高对比主题，窄侧栏不横向溢出 | styles.css、UI 验收脚本 |

暂定保留 ZCode 产品名称和品牌标识；操作图标对齐 Codex 的形状、尺寸与位置。ZCode 的账户、模型、套餐额度、MCP、手机配对等真实能力继续可达，入口按新布局组织。

能力与证据风险：

1. ZCode 是独立协议客户端。Codex 的本地/云端路由、听写、模型和权限机制不能通过换皮获得；应先核对实际后端能力，只展示可执行入口。
2. ZCode 四种权限模式必须保留现有协议语义；标签和图标可以对齐，不能将不同模式静默合并，不能改变默认权限或自动放行。
3. 尚未采集全部状态，不能承诺像素级完全一致；实现时继续补采菜单、空态、工具与 diff 状态，并记录剩余偏差。
4. 当前样式包含既有主题回归约束；切换字体、tokens 与输入区结构后，需同步更新验收断言，使其验证新的真实设计合同。
5. ZCode 独有的额度、MCP、配对功能需保留可达入口，其具体布局在操作菜单取证后确定。
