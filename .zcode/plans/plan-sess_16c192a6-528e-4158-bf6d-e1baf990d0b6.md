# 路 A 定稿：插件自带 ZCode 手机配对（relay device + 会话互通）

## 目标形态

齿轮菜单新增「手机配对」→ 弹层展示二维码 → 手机官方 ZCode App 扫码配对 → 手机出现 VSCode 工作区卡片与任务列表（含插件已有会话）→ 点开即完整 ZCode UI。配对一次后常驻：VSCode 启动即自动连 relay，手机随时可达。会话数据全在本机，relay 只转发。

## 已验证的协议事实（逆向自源码，实施时以此为准，勿重推导）

- relay：`wss://zcode.z.ai/ws`，URL 必带 `?mid=<deviceMid>` + header `X-Device-ID`。流程：`device_register_init{device_mid,pass_hash,meta}` → ack 得 `device_sid` → `auth_init(role:device)` → `auth_challenge{nonce}` → `auth_response{proof=HMAC-SHA256(passHash,"nonce|device|sid") base64url}` → `pair_status_ack{waiting|matched}`；10s jitter 心跳 `pair_status_query`，ACK 超时/断线自动重连；`KICKED`=新手机顶掉旧的（重连不关闭）。passHash=sha256(随机口令) base64。
- 二维码：`https://zcode.z.ai/remote/v4?sid&hash&t&mid&name&app_version`。手机页对 app_version 只改写不拒绝（版本门槛不存在）。
- 配对后 `{type:"data",payload}` 双向；手机发 `bootstrap-request`/`workspace-list-request`/`workspace-bridge-open` → 应答 `workspace-bridge-ready` → 之后 `rpc-frame`/`rpc-frame-ack`（base64 VSBuffer 分帧 + messageSeq/ACK/重放/高低水位流控）隧道，载荷即 `@zcode/rpc` SocketProtocol 线格式——与本地 zcode-server.cjs 的 stdio 同语言，字节直通。参考实现：桌面 `webRemoteControlTransport.ts`、`@zcode/client` 的 acknowledged relay protocol、shared 的 rpc-frame codec。
- 手机完整 UI 与 services 协议由云端页面自带；插件只需应答上述 payload、`mobile-view-state-update`、`platform-request`（v1 安全降级应答）。

## 会话互通机制（用户已拍板：必须同步插件已有会话——已验证免费成立）

- 【事实修正】agent 会话存储是 **SQLite `~/.zcode/cli/db/db.sqlite`**（session/message/part 表），非 JSONL；tasks 索引在 `~/.zcode/v2/tasks-index.sqlite`。插件与 zcode-server 同 HOME + 同 cwd → 同一 store。
- 手机打开工作区后，services 的 TaskIndexSyncer 订阅 agent `sessions-index` topic，种子快照来自共享 store 中该工作区**全部**会话（不分创建者）→ 插件已有会话自动出现在手机任务列表；taskId 即 sessionId，`session/resume` 续聊。手机新建的会话同样落共享 store，插件经自身 app-server 的 `session/list`+`session/resume` 可接续。
- 并发边界（v1 诚实约束）：无跨进程会话所有权，同一会话两端同时发消息会内存分叉（SQLite 只保证不损坏）。缓解：插件构造手机首页任务快照时**隐藏 busy 会话** + 面板文案提示「同一会话勿两端同时发送」。真互斥（插件空闲时才放行 resume）二期再做。
- 兜底路径（若播种不生效）：仿 `restore-legacy-sessions` 插件的双 DB 注入模式，二期备用。

## 关键决策

- 插件与桌面端配对身份隔离（各自 deviceMid/passHash），同一台 Mac 两个入口互不干扰，与官方桌面+CLI 共存形态一致。
- zcode-server 不打包进 vsix（体积），走约定路径 + 配置覆盖，遵循插件「可执行资产在扩展外」的既有范式。
- relay 用官方生产服务，用户账户体系内使用（同桌面行为）；凭据纪律：passHash 仅本地/协议字段，禁日志。

## 风险

- M0 闸门：构建链未装/装机 CLI 存储与 v3.15.1 源码不一致/任务列表播种不生效——任一出现即停下评估（兜底：双 DB 注入）。
- 双端并发同一会话的运行时分叉——v1 以首页 busy 隐藏 + 使用纪律缓解，明确告知边界。
- relay 为官方生产服务，协议演进需跟版；单手机限制（KICKED）是官方设计非 bug。
